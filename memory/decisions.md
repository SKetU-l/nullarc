# Архитектурные решения и обоснования (Decisions)

### ADR-001: Разделение ролей "Host Controller" и "Target Tester"
- **Дата:** 11.10.2026
- **Статус:** Принято
- **Контекст:** Разработка ведется на основном ПК (`drip-pc`, AMD Ryzen 5 5600X, GPU RDNA 1 Navi 10). Целевой GPU архитектуры RDNA 3 находится на ноутбуке.
- **Решение:** 
  1. `drip-pc` выступает исключительно как станция разработки, сборки и хостового тестирования логики.
  2. Никакие модули ядра или экспериментальные драйверы не загружаются на `drip-pc`.
  3. Аппаратное тестирование производится на ноутбуке изолированно через сеть (SSH / автоматизированные скрипты стенда).

### ADR-002: Первоочередное переиспользование модульной структуры Cobalt64
- **Дата:** 11.10.2026
- **Статус:** Принято
- **Контекст:** Проект Cobalt64 (`Almosst-DEV/Cobalt64`) предоставляет готовую, разделенную на уровни архитектуру драйвера:
  - UserClient / ABI (`N48N`);
  - ReBAR planning (`rebar_pure.h`);
  - Winsys бэкенд Mesa RADV;
  - Транслятор Metal-on-Vulkan;
  - Юнит-тесты на чистых функциях (pure functions).
- **Решение:** Переиспользовать архитектурную модель UserClient, логику ReBAR, winsys RADV и Metal-on-Vulkan. Заменить аппаратно-зависимые модули инициализации IP (GFX, GMC, PSP, SMU, SDMA, DCN) версиями для RDNA 3, портированными из Linux ядра `amdgpu`.

### ADR-003: Приоритет нативного пути Mesa RADV над транслятором Apple GFX10.3
- **Дата:** 11.10.2026
- **Статус:** Принято
- **Контекст:** В Cobalt64 есть два пути:
  1. Устаревший путь акселератора Apple: перехват вызовов `AMDRadeonX6000` и трансляция GFX10.3 PM4 через `xlat12`. Требует закрытых фикстур Apple и сложной подмены бинарных шейдеров.
  2. Нативный путь: Mesa RADV (Vulkan) + Metal-on-Vulkan (`navi48metal`).
- **Решение:** Сфокусироваться на нативном пути (Mesa RADV + Metal-on-Vulkan). Для RDNA 3 (GFX11) Mesa RADV уже содержит полностью стабильный, высокооптимизированный компилятор и шейдерный конвейер. Это исключает необходимость сложной реверс-инженерии закрытых шейдеров Apple.
